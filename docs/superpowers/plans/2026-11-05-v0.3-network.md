# OpenWrtGUI v0.3 Network Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship OpenWrtGUI 0.3.0: a Network & DHCP screen (router addresses with a 60 s rollback and the app following a changed address, DHCP server with a conflict check, fixed addresses, active leases, Wi-Fi access by MAC, DNS, static routes and rules) and a Ports screen (front panel with per-port enable and the app's own port locked, VLAN matrix, switch port mirror).

**Architecture:** A shared `uci` layer and typed-option `forms` (moved out of `wifi/`) serve every config. New `net/` (parsers, compilers, state, services) and `ports/` (swconfig) packages produce exact previews; an `ApplyRunner` applies them two ways: plain (`uci commit` + service reload) for `dhcp`, and with rollback for every `network` change, through rpcd's own `uci apply` / `uci confirm` (what LuCI uses), so the router restores itself if the app cannot reach it again within 60 s. The simulator learns network, DHCP, switch and rollback state so e2e can apply, follow and roll back.

**Tech Stack:** as v0.2 (Python 3.13, FastAPI, asyncssh, pydantic 2; React 19, TypeScript ~5.9, Vite, TanStack Query, vitest, Playwright). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-03-openwrt-gui-design.md` (approved 2026-11-03): sections 4 (ubus first), 5 (forms from typed options, port map), 6 (safety: rollback, own path, DHCP conflict, verify by effect), 7.4 Network & DHCP, 7.5 Ports, VLANs, mirroring, 8 (parity rows Network › Interfaces, Switch, Routing, DHCP and DNS; Status › Routing), 11 (testing), 13 (O8, O9). Mockups: `docs/design/canvas/project/Network.dc.html`, `Ports.dc.html`.

## Network rules (the decisions the code must follow)

**Reads.** `uci -X show network` and `uci -X show dhcp` (`-X`: anonymous sections by their `cfgXXXXXX` names), `ubus call network.interface dump`, `ubus call network.device status`, `ubus call luci-rpc getDHCPLeases`, `ubus call luci-rpc getHostHints`, `echo "$SSH_CONNECTION"` (PC address and the router address the app's SSH uses), `cat /proc/net/arp`, `ip -j -4 route show table all`, `ip -j -6 route show table all`, `ip -j -4 rule show`, `ip -j -6 rule show`, `swconfig dev <switch> show`, `swconfig dev <switch> help`, `swconfig dev <switch> get arl_table`, `ubus call luci getSwconfigFeatures '{"switch":"<switch>"}'`, `ubus call service list '{"name":"dnsmasq"}'` (and `odhcpd`, `wifi-mirror`). Each runs as its own exec (recordings key on the exact text).

**Own path.** The own interface is the uci interface whose current IPv4 address (dump) equals the router address in `$SSH_CONNECTION` (third field). Addresses are written as `address/prefix`: a bare address is refused with "Write the address with its prefix, e.g. 192.168.1.2/24 (a bare address becomes /32 on this image)". An old-style `ipaddr` + `netmask` is read as `address/prefix` and rewritten that way (`netmask` deleted) when the address is changed.

**Script shape.** Values single-quoted (`'` written as `'\''`). A new anonymous section is `<var>=$(uci add <config> <type>)` and later lines use `<config>.$<var>.<option>`. Section deletes run last, in descending position order (deleting an anonymous section renumbers the `cfgXXXXXX` names after it), option changes first. Every compiled op that changes nothing is dropped; nothing left: "Nothing to apply: the router already has these settings."

**Two ways to apply** (one write, under the write lock, every command audited):

| Change | How |
|---|---|
| `dhcp` (DHCP server, fixed addresses, DNS) | script, `uci commit dhcp`, then `/etc/init.d/dnsmasq reload` (plus `/etc/init.d/odhcpd reload` when an `ra`, `dhcpv6` or `ndp` option changed) |
| `wireless` (Wi-Fi access, saved) | `WifiService.apply_ops` per radio (its reload, TX-mask re-apply and checks), `screen="Network"` |
| runtime only (port enable, block now, block for N s) | the commands themselves, no uci |
| `network` (interfaces, devices, routes, rules, switch VLANs, mirror) | **apply with rollback**, below |

**Apply with rollback** (rpcd, confirmed on AP2 by Task 4, open item O14 until then):
1. `ubus call session create '{"timeout":300}'` → `<sid>`; `ubus call session grant '{"objects":[["network","read"],["network","write"]],"scope":"uci","ubus_rpc_session":"<sid>"}'`.
2. One exec: `mkdir -p /var/run/rpcd/uci-<sid>`, then the script with every `uci` call as `uci -P /var/run/rpcd/uci-<sid> …` (staged in the session, not in `/tmp/.uci`).
3. `ubus call uci apply '{"rollback":true,"timeout":60,"ubus_rpc_session":"<sid>"}'` — rpcd commits, reloads the services, and restores the snapshot by itself if no confirm arrives within 60 s.
4. Drop the pooled connection; after 2 s, reconnect every 2 s for up to 40 s to the **target host**: the new address when the own interface's address changes and the router was added by that address, otherwise the router's host as it is. A host key at a new address is pinned only when it equals the one pinned for the old address (same router); a different key is not trusted, and the attempt counts as unreachable.
5. Reconnected: `ubus call uci confirm '{"ubus_rpc_session":"<sid>"}'`, `ubus call session destroy '{"ubus_rpc_session":"<sid>"}'`; the router record's `host` is updated only now. Then verify.
6. Not reconnected within 40 s: "Not applied: <router> did not answer at <target> within 40 s. The router restores its previous network settings 60 s after the change." At 65 s the app reconnects to the old host and checks `uci -X show network` equals the snapshot (check `restored`).
7. Bench Guard going live after step 3 does not stop step 5: confirming finishes the user's change, and a rollback during a run would be a second change. The result says "Confirmed although Bench Guard went live (<run>)".

Preview of a rollback change: the lines of steps 1–3 and 5 with `<sid>` shown as `<session>`, plus "Applies with a 60 s rollback: if the app cannot reach <router> at <target> again and confirm, the router restores its previous network settings by itself." When the target is not in the PC's subnet (`$SSH_CONNECTION` first field): "This PC (192.168.1.10) is not in 10.0.0.0/24: the app reaches 10.0.0.1 only through a route, otherwise the change rolls back."

**Refusals and warnings (exact text).**
- Own interface: delete → "lan carries this app's connection to <router>; it cannot be deleted here."; protocol other than static → "lan carries this app's connection to <router>; with <Protocol label> the app has no known address to reconnect to."
- Interface name: "An interface name is 1 to 15 letters, digits or _"; "There is already an interface named wan". MTU: "MTU is 68 to 9000". Gateway / DNS: "<text> is not an IPv4 address".
- DHCP: pool → "The pool 100 to 300 does not fit in 192.168.1.0/24"; lease time → "Lease time is a number with s, m, h, d or w (e.g. 12h), or infinite"; option → "DHCP option codes are 1 to 254". Turning a server on, for every other known router whose last status has `dhcp_server_on` true and an IPv4 interface in an overlapping subnet: warning "<name> already serves DHCP on 192.168.1.0/24. Two DHCP servers on one subnet hand out clashing addresses; on the bench, AP1 is the only DHCP server." Status unknown: "Could not check <name>: no status yet."
- Fixed addresses: "<text> is not a MAC address"; "f4:12:fa:f3:57:68 already has a fixed address (panel)"; "192.168.1.30 is already fixed for panel"; warning "192.168.5.10 is outside every subnet of <router>".

- VLANs: "Port LAN2 is untagged in VLAN 1 and VLAN 3; a port is untagged in one VLAN at most."; "VLAN numbers on this switch are 1 to 15"; "There is already a VLAN 3"; delete in use → "VLAN 2 carries wan (eth0.2). **Verify (checks, by effect).**

| Change | Checks |
|---|---|
| any rollback change | `reconnected` (target host answered), `confirmed` (`uci confirm` exit 0) |
| interface | `interface <name>`: `ubus call network.interface.<name> status` polled every 1 s up to 20 s: up (unless proto `none`) and, for static, the asked `address/prefix` |
| routes / rules | `route <target>`: present in `ip -j -<4|6> route show table all` (same `dst`, `gateway`, `dev`) within 20 s; a deleted one absent; rules likewise by `priority` |
| VLANs, mirror | `switch`: `swconfig dev <switch> show` has the asked VLAN members / monitor port and mirror flags, polled up to 10 s |
| dhcp | `saved` (`uci -X show dhcp` has the asked values), `dnsmasq` (`ubus call service list '{"name":"dnsmasq"}'` has a running instance) |
| port enable | `port <label>`: `enable` as asked in `swconfig dev <switch> show`; link down after a disable |
| block now | `runtime list <ifname>`: `hostapd_cli -i <if> deny_acl SHOW` (or `accept_acl SHOW` for Only listed) has / lacks the MAC |

One audit entry per write after the checks: `command="verify <what>"`, `exit_status=None`, `verify="pass"` or `"fail: <failed check names>"`.

**Ports rules.**
- External ports are the `board.json` switch ports with a role (`lan`, `wan`); the CPU port is the one with a `device` (`eth0` → VLAN devices `eth0.<vid>`). Labels: `RouterRecord.port_labels`, else `board.json`.
- Own port: the PC's MAC is the `/proc/net/arp` entry of the `$SSH_CONNECTION` PC address; if `arl_table` lists that MAC (lines `Port <n>: MAC <mac>`), that port is the own port. Else, if the own interface sits on a VLAN of this switch, the external ports of that VLAN with a link are candidates: one candidate is the own port; several are all locked as candidates. AP2 (2026-11-05): `arl_table` is empty, only port 3 (LAN1) has a link in VLAN 1, so LAN1 is the own port.
- Port enable is offered only when `swconfig dev <switch> help` lists the port attribute `enable` and `show` gives `0` or `1` for that port (`???` = not switchable). "Enable all ports" sets `enable 1` on every external port that has `0`.
- VLAN members are written as `ports='0 1 2 3 6t'` (ascending, `t` = tagged). A new VLAN is `<var>=$(uci add network switch_vlan)` with `device`, `vlan`, `ports`. VLAN numbers 1 to (`vlans` from `help`) − 1.
- Mirror (when `luci getSwconfigFeatures` has `mirror_option` and `show` has `mirror_monitor_port` and the port flags): `network.<switch section>.mirror_monitor_port='<n>'`, and per source port a `switch_port` section (`device`, `port`, `enable_mirror_rx`, `enable_mirror_tx`), reused when one exists for that port. Off: the switch section's `mirror_monitor_port` and every source flag deleted.

## Review Focus

1. The change cuts the app's path (a wrong prefix on lan, VLAN 1 without the PC's port, a rule that shadows the PC's subnet): the result is never "done"; it says not applied, and only after the app reconnects at the old address and reads the network config back equal to the snapshot does it say "restored" (Task 5 test `test_unreachable_after_apply_reports_restored`; Task 6 test `test_rollback_restores_after_deadline`).
2. lan's address changes and the app follows: it reconnects at the new address only with the identical host key, confirms there, and only then updates `routers.json`; a different key at the new address is not confirmed, so the router rolls back (Task 5 tests `test_changed_address_followed_and_record_updated`, `test_new_address_with_other_host_key_is_not_confirmed`).
3. One apply deletes two anonymous sections (two fixed addresses, or a VLAN and a route): the right sections go, because deletes run last in descending position, and a router changed since the preview gets "<router> changed since the preview" (Task 1 test `test_deletes_run_last_in_descending_position`; Task 8 test `test_deleting_two_hosts_removes_those_two`).
4. Bench Guard goes live between `uci apply` and `uci confirm`: the app still confirms and says so; it never leaves a half-applied change to roll back during a run (Task 5 test `test_guard_live_after_apply_still_confirms`).
5. The app cannot tell which switch port carries its SSH (empty ARL table, several ports with a link in its VLAN): every candidate stays locked with the "may carry" text, and Enable all still works (Task 11 test `test_candidates_locked_when_own_port_ambiguous`).
