# OpenWrtGUI v0.6b System (Status first) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A System screen per router (spec 7.11, first half): status (overview, logs, processes, live load / bandwidth / connections, diagnostics), system settings (hostname, time zone, NTP, log buffer, remote syslog), services and `rc.local`, scheduled tasks, reboot, and backup download. Access, SSH keys, HTTP(S), LEDs, mount points, restore and reset to defaults are plan v0.6c.

**Architecture:** A new `system/` package reads what LuCI's own pages read (`ubus call system board|info`, `logread`, `dmesg -r`, `top -bn1`, `/proc`, `ubus call rc list`, `/etc/rc.local`, `/etc/crontabs/root`, `uci -X show system`, `ubus call luci getTimezones`) and writes through the paths the app already has: uci changes through `net_plan` and `ApplyRunner`'s plain apply (no rollback: none of these cuts the app off), files through the audited heredoc (`fw/tables.py` `heredoc`), services through `/etc/init.d/<name> <action>` proven by re-reading `rc list`, a reboot through the router-side timer (`timer.py`) and the come-back wait that flashing uses, and the backup through the byte stream (`sysupgrade -b -`). A sampler streams load, bandwidth and the connection count over `/ws/system/{id}` like RF live. The simulator gets a `SimSystem`.

**Tech Stack:** as v0.6a (Python 3.13, FastAPI, asyncssh, pydantic 2; React 19, TypeScript, Vite, TanStack Query, uPlot, vitest, Playwright). No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-03-openwrt-gui-design.md`: section 6 (safety), 7.11 System, 8 (LuCI parity: Status › Overview, System log, Kernel log, Processes, Realtime graphs; System › System, Startup, Scheduled tasks, Backup / Flash firmware, Reboot; Network › Diagnostics), 11 (testing), 13. Scope split agreed with Dmitry 2026-11-09 (two plans, Status first; reset to defaults later, simulator only).

## Global Constraints

- Branch `feat/v0.6-system` from `feat/v0.6-lte` (its PR goes first; merge `master` in after it lands). Conventional commits. One PR to `master`; Dmitry merges. Branches are never deleted.
- Nothing is created on GitHub (PR, release, tag, label, milestone change, issue comment) without Dmitry's explicit go.
- Bench: hardware steps use AP2 (192.168.1.2) only, with Bench Guard clear and the parent session's "AP2 free" (the txctl session told before any write window). AP1 and AP3 are never contacted. A step that changes AP2 (uci system, a service action, a cron or rc.local edit, a reboot) needs Dmitry's OK for that window first; AP2 ends as found (`uci -X show system`, `/etc/rc.local`, `/etc/crontabs/root`, every service's enabled and running state, radio parked).
- Agents never type a router password. A backup holds the router's password hash, its SSH host keys, the app's key line and the Wi-Fi keys: it is saved only under the app's data folder with the user-only ACL, never in a test fixture, a log or the audit log.
- "The app sends the exact command text it shows in the preview." "A write is reported as done only when the effect is proven."
- Every write is checked by Bench Guard, runs under the router's write lock and leaves an audit entry per command (`screen="System"`). While Bench Guard is live, writes and diagnostics are refused with 423; reads keep working.
- Every value put into a command matches a `re.fullmatch` rule first and is `shell_quote`d; a file body goes through `heredoc` (a line reading `OWG` is refused).
- Every tab and card has a "?" help next to its heading and every main button a `HelpTip`, from `docs/manual/System.md` (`manual.test.ts`); the page goes in `_Sidebar.md`.
- Light and dark; e2e at 1440 and 375 px with no horizontal page scroll; controls at least 44 px high.
- `uv run pytest --cov=openwrtgui --cov-fail-under=80`, `uv run ruff check src tests tools`, `uv run ruff format --check src tests tools`, `uv run mypy`, `npm run lint`, `npx tsc -b`, `npm test`, `npm run e2e` all green. After an API change: `uv run python tools/dump_openapi.py`, then `npm run gen:api`.
- Version stays `0.6.0`.

Proof: the saved config, plus the live hostname (`ubus call system board`) and `cat /tmp/TZ` | LuCI writes the same options and calls the same init scripts; none of them touches the network, so no rollback | 8 |
| D6 | **Services: every init script from `rc list`**, start/stop/restart/enable/disable proven by re-reading `rc list`. The app's own path (`dropbear`, `network`, `firewall`, `rpcd`, `uhttpd`, `log`, named in `PROTECTED`) offers restart only, never stop or disable; `network`, `firewall`, `wpad`, `dnsmasq` restart carries the network-reload warning. | D10 | **Processes are read-only in v0.6b** (no hang up / terminate / kill); the terminal stays the way to signal a process | Signalling needs its own protected list (netifd, dropbear, procd...) and Dmitry's call; it can come with v0.6c | 5, 14 |

| D12 | **Two AP2 windows**: HW-1 read-only records the reads above (`--set system`; not the backup archive: only its size); HW-2 (Dmitry's OK) changes the hostname and back, adds and removes one cron line, restarts `sysntpd`, and (separately, opt-in `--allow-reboot`) reboots AP2 once and waits for it | Nothing of the System reads is recorded yet (fact sheet: no `logread`, `dmesg`, `top`, `rc list`, crontab, rc.local, time zone list) | 17, 18 |

## Review Focus

1. A router without a file or a package the screen expects (no `/etc/crontabs/root`, no `/etc/rc.local`, `luci getTimezones` missing on a non-LuCI image, `nf_conntrack` module not loaded): the tab says what is missing and keeps the rest; an empty crontab is "no tasks", not an error (Task 5 `test_status_without_optional_parts`, Task 10 `test_no_crontab_file_is_no_tasks`).
2. Text that would break a write: an `rc.local` or crontab line reading `OWG`, a crontab line with 4 fields or `61 * * * *`, a command with a newline, 9 KiB of text, a hostname `-x`/`a_b`/64 chars, a time zone not in the router's list: refused before anything is sent (Task 8 `test_system_settings_refusals`, Task 10 `test_crontab_refusals`, `test_rc_local_refusals`).
3. The app's own path: stop or disable of `dropbear`, `rpcd`, `network`, `firewall`, `uhttpd` refused with the reason; restart of `network`/`firewall` carries the network-reload warning (Task 9 `test_the_apps_path_is_restart_only`).
4. A reboot that never comes back, or comes back too fast to be a reboot (uptime older than the arm time): the job ends "not back after 300 s" or keeps waiting, never "done" (Task 11 `test_reboot_proven_by_a_fresh_uptime`, `test_reboot_that_does_not_come_back`).
5. A run starts while a diagnostic or a write is planned: 423 with the run's name; a backup and the reads still work (Task 7 `test_diagnostics_wait_for_the_run`, Task 12 `test_backup_during_a_run`).

## Rules (the decisions the code must follow)

- Overview: model, board, firmware (`release.description`, revision), kernel, hostname, local time, uptime, load (1/5/15, from `system info` /65536), memory (total, available), storage (root and tmp from `system info`), and links to Network's live routes and RF live.
- Logs: `logread -l <n>` lines parsed as `<weekday> <month> <day> <hh:mm:ss> <year> <facility>.<level> <source>[pid]: <message>`; `dmesg -r` lines as `<level>[seconds] message`; filter by text and level in the browser; Follow re-reads every 5 s while on.
- Processes: `top -bn1` rows (PID, PPID, user, state, VSZ, %VSZ, %CPU, command), sorted by %CPU; the header lines (`Mem:`, `CPU:`, `Load average:`) feed the overview's CPU line.
- Settings ops are uci ops on the `-X` section names; unchanged values are dropped by `net_plan`; `zonename` from the request, `timezone` from the router's list for that name.
- Services row: name, enabled, running, start/stop priority (from `rc list`), protected (bool, with the reason).
- Every write's audit `screen` is `"System"`.
