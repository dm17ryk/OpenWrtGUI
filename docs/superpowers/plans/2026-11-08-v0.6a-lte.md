# OpenWrtGUI v0.6a LTE Modem Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An LTE screen per router (spec 7.10): modem status with signal quality and history, the `network.lte` settings with the board's rules built in (lte_4 stays DHCP, the modem's autoconnect stays off), modem info, connect and disconnect, a safe modem reboot, and an AT console. Reset to defaults stays open (O1).

**Architecture:** A new `lte/` package reads the modem the way the bench image already does: `uqmi -s -d /dev/cdc-wdm0 -t 2000` for the serving system and signal (the same calls `dwr921-internet-led` makes every 30 s), busybox `microcom` for AT (on the port that answers `AT`), and netifd's `ubus` status for the session, address and counters. A sampler streams the signal over a WebSocket, like RF live. Settings reuse v0.3's interface plan for `network.lte` (one new request field, `auto`, and one new refusal, `dhcp=0` on a qmi interface). Writes (connect, disconnect, reboot, non-query AT) go through Bench Guard, the write lock and the audit log. The simulator gets a `SimModem`.

**Tech Stack:** as v0.5 (Python 3.13, FastAPI, asyncssh, pydantic 2; React 19, TypeScript, Vite, TanStack Query, uPlot, vitest, Playwright). No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-03-openwrt-gui-design.md`: router facts (lines 35-41: BM806C, QMI on `/dev/cdc-wdm0`, AT on ttyUSB, `lte_4` must stay DHCP), section 5 (LTE capability), 6 (safety), 7.10 LTE modem, 8 (LuCI parity: Network › Interfaces with protocol qmi → LTE modem), 11 (testing: `uqmi` and AT parsers), 12 (v0.6 row), 13 (O1-O3). Roadmap milestone "v0.6 LTE and System"; the System screen (7.11) is plan v0.6b.

## LTE rules (the decisions the code must follow)

**Reads** (each its own exec; device `/dev/cdc-wdm0` from `network.lte.device`, matched by `^/dev/cdc-wdm[0-9]$`):
- `uqmi -s -d /dev/cdc-wdm0 -t 2000 --get-serving-system` → JSON: `registration` (`registered`, `searching`, `not_registered`, `registering_denied`, `unknown`), `radio_interface` (list, first entry shown: `lte`, `umts`, `gsm`, …), `roaming` (bool, may be absent), `plmn_mcc`, `plmn_mnc`, `plmn_description`.
- `uqmi -s -d /dev/cdc-wdm0 -t 2000 --get-signal-info` → JSON with `type` and the values for that type: `lte`: `rssi`, `rsrq`, `rsrp`, `snr`; other types: whatever of `rssi`, `ecio`, `rscp` is present (shown without a label).
- `uqmi -s -d /dev/cdc-wdm0 -t 2000 --get-device-operating-mode` → a JSON string (`online`, `low_power`, …).
- `ubus call network.interface.lte status` → `up`, `pending`, `uptime`, `l3_device`; `ubus call network.interface.lte_4 status` → `ipv4-address[0].address`/`mask`, `pending`; `ubus call network.device status '{"name":"<l3_device>"}'` (name `^[A-Za-z0-9._-]{1,15}$`) → `statistics.rx_bytes`, `tx_bytes`.
- AT (D4): `printf '%s\r' <shell_quote(command)> | timeout 10 microcom -t 2000 -s 115200 /dev/ttyUSB<n>`; port list from `ls /dev/ttyUSB*`; port `^/dev/ttyUSB[0-9]$`. The answer is the lines after the echo up to `OK`, `ERROR` or `+CME ERROR: <n>` (with or without echo; `\r` stripped). Modem info: one exec sending `AT+CGMI\rAT+CGMM\rAT+CGMR\r`; operator: `AT+COPS?` → `+COPS: <mode>,<format>,"<name>",<act>`; mode order: `AT+BMMODODR?` → `+BMMODODR: <code>`.
- A read that exits non-zero, times out, or prints something that is not JSON is "no answer" for that part; the other parts still show.

**Writes** (preview → digest → Bench Guard → write lock → audit, `screen="LTE"`):
- Connect: `ifup lte`; proven when `network.interface.lte` is `up` within 60 s (polled every 2 s); the result also says whether lte_4 got an IPv4 address ("no address yet: waiting for the carrier's DHCP" is not a failure). Disconnect: `ifdown lte`; proven when `up` is false within 20 s.
- Reboot modem (D6): `uqmi -s -d /dev/cdc-wdm0 -t 3000 --set-device-operating-mode low_power`, read back until `low_power` (3 tries, 1 s apart), `uqmi -s -d /dev/cdc-wdm0 -t 3000 --set-device-operating-mode online`, read back until `online`, then `ifup lte` and the connect proof. A failed read-back stops: "The modem did not go <mode>; it may need ifup lte or a power cycle".
- Settings: v0.3's interface plan for `network.lte` (rollback 60 s, as every interface change), with D7, D8, D9. The form: APN, authentication (`none`, `pap`, `chap`, `both`), user name, password, PIN (`^[0-9]{4,8}$`), PDP type (`ipv4`, `ipv6`, `ipv4v6`), MTU (68-9000; AP2 1420), metric, bring up at boot, default route; every other qmi option under All options.
- AT non-query (D5): the command line exactly as typed, audited; no proof beyond the modem's `OK`.
- One LTE write at a time per router: a second while one runs → 409 "An LTE action is already running on <router>".
- Reset modem to defaults: not built (O1, Dmitry 2026-11-08). The Actions card says "Reset to defaults: the BM806C's command is not known yet".

**State shown:** registration, radio, roaming, operator (D2); RSSI/RSRP/RSRQ/SNR with labels (D11); session uptime (lte), IPv4 (lte_4), RX/TX bytes (l3 device); operating mode; manufacturer, model, firmware (D3); mode order (D10); the modem's autoconnect (D7); "lte_4 stays DHCP" note.

## Review Focus

1. The modem is absent or re-enumerating (no `/dev/cdc-wdm0`, uqmi times out, `microcom` finds no tty): the screen says what it could not read and keeps the rest; the sampler keeps trying every 10 s; actions refuse with the reason; nothing crashes (Task 7 `test_state_without_a_modem`, Task 8 `test_sampler_survives_missed_reads`).
2. uqmi answers for a non-LTE radio or with keys missing (`radio_interface` absent, `type: "umts"` with `ecio`/`rscp`, `registration: "searching"`): parsed and shown as far as present, no label for a value without one (Task 3 `test_signal_of_other_radios`, `test_serving_system_partial`).
3. AT console text with quotes, `$(...)`, a newline, 10 000 characters, or not starting with `AT`: refused before anything is sent, or sent shell-quoted exactly as typed; during a run a non-query is refused with 423 (Task 10 `test_at_console_refuses_unsafe_text`, `test_at_console_during_a_run`).
4. A settings change that would cut LTE downlink (`dhcp=0`, protocol `static` on lte, an edit of lte_4): refused with the reason; MTU outside 68-9000 refused (Task 6 `test_qmi_dhcp_stays_on`, Task 11 `test_settings_refusals`).
5. Two LTE actions at once (reboot while connect runs) or a read during netifd's setup: the second action gets 409; a read that collides with another uqmi user is a missed sample, not a state change (Task 9 `test_one_lte_action_at_a_time`, Task 8 `test_sampler_survives_missed_reads`).
