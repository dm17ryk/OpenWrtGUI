# OpenWrtGUI v0.5 Discovery and Images Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship OpenWrtGUI 0.5.0: import a sysupgrade image and build a profile from it (or from a router's `/rom`), show on a new Discovery screen how each router differs from its image (files and packages added after flashing, config changed from the image defaults, firmware match), list the custom packages and unknown custom programs with their usage text, "Run `--help`" and "Promote to a card", and flash a router from an imported image with board, hash and `sysupgrade -T` checks, reconnect and revision check.

**Architecture:** A new `images/` package parses a sysupgrade `.bin` on the PC (uImage header, squashfs root, fwtool metadata trailer) and reads the squashfs with PySquashfsImage into a `Profile` (packages, files, kernel modules, PATH programs, config defaults, custom packages with usage text), stored under the data folder's `profiles/`. A `discovery/` package reads a router's overlay, package database, configs and firmware partition and diffs them against the matched profile; it also owns tool descriptors (promoted cards) and custom services. A `flash/` package uploads an image over the existing SSH transport, validates it on the router, starts `sysupgrade` through v0.4's router-side timer, waits for the router to come back and proves the new revision. The simulator learns `/rom`, `/overlay/upper`, the apk database, `/proc/mtd`, uploads and a reboot, so e2e can import, diff, promote and flash.

**Tech Stack:** as v0.4 (Python 3.13, FastAPI, asyncssh, pydantic 2; React 19, TypeScript ~5.9, Vite, TanStack Query, vitest, Playwright). One new runtime dependency: `PySquashfsImage` (pure Python, LGPL; reads xz squashfs with the standard library's `lzma`). Decision D1 below.

**Spec:** `docs/superpowers/specs/2026-11-03-openwrt-gui-design.md` (approved 2026-11-03): sections 4 (prober: image profiles, pure-Python squashfs reader; data folder `profiles/`), 5 (image profile, on connect, capabilities, forms: the image default per option), 6 (safety), 7.1 (Needs attention: files added after flashing; ownership tags, deferred from v0.4), 7.5 (wifi-mirror note), 7.8 Discovery and tools, 7.11 (Flash firmware from an imported image), 10 (manual page "Adding a router family (image import)"), 11 (testing), 12 (v0.5 row), 14 (the app imports images, it does not build them). Issues: milestone "v0.5 Discovery and images" (#4).

## Image rules (the decisions the code must follow)

Measured on the bench image (`D:\Essence_SC\DWR_921-c3-uboot\openwrt-ramips-mt7620-dlink_dwr-921-c3-uboot-squashfs-sysupgrade.bin`, 11 272 478 B, sha256 `d340a53f2de057a8d1d703239a22e9bd24b834dcd9a0e7397bf80861ff25cc10`; the `…qmifix3-20260815-095045…` file in the same folder is byte-identical):

| Part | Offset | Size | Content |
|---|---|---|---|
| uImage header | 0 | 64 | magic `27 05 19 56`, name `DWR_921`, compression 3 (lzma), data size 2 983 529 |
| kernel | 64 | 2 983 529 | |
| squashfs | 2 983 593 | 8 271 661 (`bytes_used`) | v4.0, xz, block 262 144, 1832 inodes, flags `0x2c0` |
| padding + `de ad c0 de` | 11 255 254 | 16 942 | padded to the 64 KiB boundary 11 272 192, then the jffs2 end marker |
| fwtool metadata | 11 272 196 | 282 | 8-byte header (version 0, flags 0) + JSON (258 B) + trailer `46 57 78 30` (`FWx0`), crc32, type 1, size `0x11a` |

Metadata JSON: `{"metadata_version": "1.1", "compat_version": "1.0", "supported_devices": ["dlink,dwr-921-c3-uboot"], "version": {"dist": "OpenWrt", "version": "SNAPSHOT", "revision": "r35692-b8bffeefdf", "target": "ramips/mt7620", "board": "dlink_dwr-921-c3-uboot"}}`.

**Parse** (`images/sysupgrade.py`), in order; each refusal names the file:
- Larger than 64 MiB: "<file> is larger than 64 MB; a sysupgrade image for these routers is not".
- fwtool trailers, read from the end while the last 16 bytes start with `FWx0` (big-endian: magic, crc32, type u8, 3 pad bytes, size u32 = block length including the trailer): type 1 → metadata JSON after the block's 8-byte header; type 0 → signature (kept as present/absent, not checked); anything else stops the walk. No trailer: metadata is `None` ("No fwtool metadata: the image does not say which boards it is for", shown, not a refusal).
- uImage header at 0 (optional; other targets have none): read name and data size.
- squashfs: the first `hsqs` whose superblock says version 4.0 and whose `bytes_used` ends inside the file; none → "No squashfs root file system in <file>" (the profile can then be built from a router's `/rom`, below).
- Compression other than xz, gzip or lzma: "<file> uses <name> compression, which this app cannot read".
- Root file system read with `PySquashfsImage.SquashFsImage(io.BytesIO(data[offset:offset + bytes_used]))`.

**Profile** (`images/profile.py`), from the root file system:
- `release`: `/etc/openwrt_release` as key/value (`DISTRIB_REVISION`, `DISTRIB_TARGET`, `DISTRIB_ARCH`, `DISTRIB_DESCRIPTION`). Missing → "<file> has no /etc/openwrt_release; it is not an OpenWrt root file system".
- `boards`: metadata `supported_devices` (the `ubus call system board` `board_name` form, e.g. `dlink,dwr-921-c3-uboot`); empty when there is no metadata.
- `packages`: `/lib/apk/db/installed` blocks (blank-line separated; one field per line, `<letter>:<value>`): `P` name, `V` version, `T` description, `o` origin, `L` license, `U` URL, `D` depends, and the owned files (`F:` directory lines followed by `R:` file lines, joined as `/<F>/<R>`). Images with `/usr/lib/opkg/status` instead: the same fields from `Package:`, `Version:`, `Description:`, `License:`; files from `/usr/lib/opkg/info/<name>.list`. Neither → "<file> has no package database (apk or opkg)".
- `custom`: packages with empty `L` and empty `U` (D8). On the bench image: `dwr921-diag` 2, `dwr921-internet-led` 4, `dwr921-portctl` 2.
- `usage` per custom package file that starts with `#!`: the text of the first heredoc inside a `usage()` function (`cat <<'EOF'` … `EOF`, any delimiter); else the lines matching `(?i)^\s*(echo|printf)\s.*usage:`; else the first line containing `Usage:`; at most 4 KB. On the bench image `dwr921-portctl` → `Usage: dwr921-portctl {port-status|port-enable|port-disable} {lan1|lan2|lan3|lan4|wan}`; `dwr921-internet-led` → none.
- `files`: every non-directory entry: path, kind (`file`, `link`, `other`), size, mode, link target, and sha256 for regular files up to 1 MiB (larger: `None`).
- `modules`: base names of `*.ko` under `/lib/modules/`; `programs`: entries directly in `/bin`, `/sbin`, `/usr/bin`, `/usr/sbin`, `/usr/libexec`.
- `configs`: each regular file in `/etc/config/` parsed as uci (`images/uci_file.py`) into the `uci show <config>` form (`cfg.name=type`, `cfg.@type[n]=type` for anonymous sections counted per type from 0, `cfg.sec.opt='v'`, list options as `'a' 'b'`, quotes as uci prints them: `'` inside a value becomes `'\''`).
- `services`: names in `/etc/init.d/`; `uci_defaults`: names in `/etc/uci-defaults/`.
- `key`: `ProfileKey(board, revision, sha256)` with `board` = the first `supported_devices` entry (or `DISTRIB_TARGET` with `/` → `_` when there is none), `revision` = `DISTRIB_REVISION`, `sha256` = the image file's.
- `firmware_len`: the squashfs end offset (11 255 254 on the bench image); `None` without a uImage header in front of the squashfs.

**From a router's `/rom`** (when an image cannot be parsed or none is at hand): `cat /rom/etc/openwrt_release`, `cat /rom/lib/apk/db/installed` (or opkg's status), `find /rom -xdev ! -type d -exec ls -ldn {} +`, `ls /rom/etc/config` + `cat /rom/etc/config/<name>` each, `ls /rom/etc/init.d /rom/etc/uci-defaults`, `ubus call system board` for the board. Usage text from `head -c 6000 /rom<path>` of each custom package file. Key `ProfileKey(board_name, revision, "rom")`; no file hashes, no `firmware_len`: "Built from <router>'s /rom: import the image file to check the firmware or to flash".

**Store**: `<data>/profiles/<board>/<revision>-<sha256[:12] or "rom">/` with `profile.json` (the profile, schema version 1) and `image.bin` (D2). Importing the same sha256 again: "This image is already imported (<board> <revision>)". Deleting a profile deletes its folder.

## Discovery rules

**Match.** A router matches the profile whose `board` equals its `ubus call system board` `board_name` and whose `revision` equals its `/etc/openwrt_release` `DISTRIB_REVISION`; more than one (an image and a `/rom` profile): the image one. None: "No imported image for <board> <revision>. Import its sysupgrade image (Settings › Images), or build a profile from this router's /rom."

**Reads** (each its own exec):
- `find /overlay/upper -xdev ! -type d -exec ls -ldn {} +` (busybox `ls -ldn` lines: mode, links, uid, gid, size or `major, minor`, date, path, ` -> target` for links). `/overlay/upper` missing: "<router> has no overlay (a read-only root?)" and the overlay parts are empty.
- `cat /lib/apk/db/installed` (or opkg's status).
- `ls /etc/config`, then `uci show <config>` for each config that is in the profile or live.
- `sysupgrade -l` (the files a keep-settings flash keeps).
- `cat /etc/openwrt_release`, `ubus call system board` (identity, as v0.1 reads it).

**Overlay difference:**
- `added`: a regular file or link in the overlay whose path is not in the profile ("added after flashing").
- `replaced`: a path that is in the profile ("changed from the image"; the profile's sha256 is shown, the router's is read only for Copy).
- `deleted`: a character device `0, 0` (an overlayfs whiteout) on a profile path ("deleted from the image").
- `packages`: `added` (live name not in the profile), `removed` (profile name not live), `changed` (same name, other version).
- `configs`: per config, `changed` options (`key: image → router`), `added` options, `removed` options; a config with no image default is "created at first boot" (on the bench image `network`, `wireless`, `system` and others are), listed without a diff.
- `kept_on_flash`: overlay paths `sysupgrade -l` lists; the rest is "lost on a flash".

**Firmware check** (D4): the `firmware` partition from `cat /proc/mtd` (`mtd<N>: <size> <erasesize> "firmware"`), then `dd if=/dev/mtdblock<N> bs=65536 count=<ceil(firmware_len / 65536)> 2>/dev/null | head -c <firmware_len> | sha256sum`; equal to sha256 over the image's first `firmware_len` bytes → "The firmware matches <image>"; else "The firmware differs from <image> (flashed from another build, or changed since)". Refused while Bench Guard is live: "The firmware check reads 11 MB of flash; not while <run> runs". No `firmware_len` (a `/rom` profile): "Import the image file to check the firmware". No `firmware` partition: "<router> has no mtd partition named firmware".

**Capability map:** each capability (spec 5) is `in image` when every file it needs is in the profile, `added after flashing` when one is only in the overlay, `missing` otherwise (the reason as today).

**Copy files** (to the same or another router, and back after a flash): plain files and links only, each at most 1 MiB, at most 4 MiB in all; never `/etc/shadow`, `/etc/dropbear/*` or `/etc/owg/*` of another router ("<path> is the router's own key or password; it is not copied"). Read with `cat <path>` (bytes from stdout); written with `mkdir -p <dir> && cat > <path>` fed the bytes on stdin, then `chmod <mode> <path>`; links with `ln -sfn <target> <path>`. Verified with `sha256sum <path>` (links: `readlink`). Each file is a preview line `upload <path> (<bytes> B, sha256 <12 hex>) to <router>:<path>`.

**Reflash checklist:** a saved list (`<data>/reflash/<router id>-<YYYYMMDD-HHMMSS>.json`): profile key, overlay difference, packages added, and the files that are lost on a flash, with their contents (up to the Copy limits) so they can be copied back. Saved by "Save as reflash checklist" and automatically before every flash.

## Tools rules

**Custom packages** (Discovery › Your custom packages), from the image's package database and the router's (one installed after flashing is marked "added after flashing"; its usage text is read from the router with `head -c 6000 <path>`), one row each: name, version, description, its programs with usage text, and one of:
- `card` when a built-in screen uses it (v0.5 table: `dwr921-portctl` → Ports screen), or a promoted card exists for one of its programs;
- `service` when it ships `/etc/init.d/<name>` (custom services rule below);
- `no card yet` with Run `--help` and Promote per program.

**Programs added after flashing**: programs in the PATH directories that the overlay added and no package owns (a script copied by hand). Same row shape; with no card they show Run `--help` and Promote.

**Run `--help`** (D3): `timeout 5 <path> --help 2>&1 | head -c 8192` with `<path>` matching `^/[A-Za-z0-9._/+-]{1,200}$`; previewed with "<name> runs on <router> for at most 5 s. A program that does not know --help may do something else."; refused during a run; audited; the output is shown as text.

**Promote to a card** (D9): a descriptor `ToolCard(board, path, name, commands)` with `ToolCommand(label, args, write)`; an arg is a literal (`^[A-Za-z0-9._:=,/@+-]{1,64}$`) or a parameter `{name}` with `ToolParam(name, kind, choices, pattern, minimum, maximum)`, `kind` one of `choice`, `text` (default pattern `^[A-Za-z0-9._:-]{1,64}$`), `number`. The dialog is filled from the first `Usage:` line: the first `{a|b|c}` group gives one command per alternative, each later `{…}` group a `choice` parameter, `[…]` parts are left out. Limits: name 1–40 characters, label 1–40, at most 12 commands and 4 parameters each. Running a command: `<path> <arg …>` with every arg `shell_quote`d; `write: true` → preview, Bench Guard, write lock, audit (screen `Discovery`); `write: false` → runs during a run too, audited.

**Custom services** (D10): a service whose `/etc/init.d/<name>` comes from a custom package or the overlay. State: `ubus call service list '{"name":"<name>"}'` (running = an instance with `"running": true`) and `/etc/init.d/<name> enabled; echo $?` (0 = enabled). Start, Stop, Restart: `/etc/init.d/<name> start|stop|restart`, verified by the state read polled every 1 s for up to 10 s (Stop: no running instance; Start, Restart: a running instance). Name `^[A-Za-z0-9._-]{1,64}$`.

## Flash rules

**Preconditions** (each refusal exact):
- A profile from an image file (not `/rom`): "Flash needs the image file: import it in Settings › Images".
- The stored `image.bin` still has the profile's sha256: "<image> changed on disk since it was imported; import it again".
- The router's `board_name` is in the image's `supported_devices`: "This image is for <supported devices>; <router> is <board_name>". No metadata: "The image does not say which boards it is for; flash it with LuCI or sysupgrade -F by hand".
- Bench Guard clear (the usual 423).
- `/proc/meminfo` `MemAvailable` at least the image size plus 4 MiB, and `df -k /tmp` free at least the image size: "<router> has <n> MB of RAM free; the image needs <m> MB in /tmp", `<n>` = the smaller of the two free figures in whole MB rounded down, `<m>` = image size + 4 MiB in MB rounded up (16 for the bench image). Task 7 measures AP2; the 4 MiB margin is checked there.
- A warning, not a refusal, when the router serves DHCP on the interface that carries the app (v0.3 `NetworkState`): "<router> hands out addresses on <interface>. Devices there get no new address while it flashes (about 3 minutes)."

**Steps** (the preview lists them all; each a line):
1. `mkdir -p /tmp/owg`
2. `upload <image> (<bytes> B, sha256 <12 hex>) to /tmp/owg/fw-<sha256[:12]>.bin` (bytes on stdin of `cat > /tmp/owg/fw-<sha256[:12]>.bin`, streamed in 64 KiB chunks with progress).
3. `sha256sum /tmp/owg/fw-<sha256[:12]>.bin` equals the image's.
4. `ubus call system validate_firmware_image '{"path":"/tmp/owg/fw-<sha256[:12]>.bin"}'` has `"valid": true` (else the tests that failed, e.g. `fwtool_device_match`), and `sysupgrade -T /tmp/owg/fw-<sha256[:12]>.bin` exits 0. Either fails → `rm -f` the file, "<router> refused the image: <reason>".
5. Keep settings and `/etc/owg` exists: `grep -qx /etc/owg/ /etc/sysupgrade.conf || echo /etc/owg/ >> /etc/sysupgrade.conf` (D5).
6. The reflash checklist is saved (on the PC).
7. `timer.arm_command("flash", 2, ["sysupgrade [-n] /tmp/owg/fw-<sha256[:12]>.bin"])`: the router starts `sysupgrade` 2 s after the app's exec returns, so the arming exits 0 and is audited; `-n` without keep settings.
8. The pool holds the router (v0.4 `ConnectionPool.hold`); the app closes its session.

**Come back** (keep settings): every 5 s for up to 10 minutes, a fresh connection with the pinned host key. Proven when `/etc/openwrt_release` has the profile's revision, `ubus call system board` the same `board_name`, and `/proc/uptime` is less than the time since step 7. Result: "Flashed <router> with <revision> in <m> min <s> s". A different host key: the v0.4 reason ("<router> answers with another host key …") and no auto-accept. Ten minutes without an answer: "<router> did not come back within 10 minutes. It may still be writing flash: do not power it off; check its LEDs, then try Reconnect."

**Without keeping settings** (D6): an extra confirmation "I have isolated <router> from the bench LAN" is required; after step 7 the router entry gets `reflashed_without_settings` and shows "Reflashed without settings: it comes back as 192.168.1.1 with no password. Connect it alone to this PC, then Add it again." The wizard (spec 5, step 2) shows the new host key as expected only when that entry is pending and the board and revision it reads before pinning equal the image's; otherwise the usual changed-key block.

**After** (keep settings): Discovery opens on the router with the lost files of the checklist pre-ticked for "Copy back".

**How uploads run.** `ApplyRunner._plain` sends text commands only, so copy and flash run their own steps: `guard.require_clear()`, `async with pool.write_lock(rec.id)`, plan again and compare the digest (`PreviewChanged` on a mismatch), then each step through `run_audited` or the new `run_audited_upload`, stopping at the first failure. An upload's preview and audit line is the exact command plus a comment: `cat > /tmp/owg/fw-d340a53f2de0.bin  # stdin: openwrt-…-sysupgrade.bin (11272478 B, sha256 d340a53f2de0)`.

**Scope notes (decided for v0.5).**
- In: spec 5 (image profile, on connect, capability map), 7.8 (Discovery, except the phase 2 tool pages), 7.11's "Flash firmware from an imported image", 7.1's "files added after flashing" and the ownership tags deferred from v0.4, the manual page "Adding a router family (image import)".
- Out: the image default per option in the All options editors (spec 5, Forms). On the bench image `wireless` and `network` are created at first boot, not shipped, so the column would be empty on every editor that exists; it comes with v0.6's System forms. Baselines and known-writer signatures (spec 5, O10): not in the v0.5 row. Backup, restore and reset to defaults (spec 7.11): v0.6.
- "What the router says about itself" (spec 7.8) is the existing router overview (`RouterOverview.tsx`: sources, LuCI pages, port labels); Discovery links to it instead of repeating it.
- Discovery reads run on demand (opening the screen, Refresh) and once per connect for the dashboard summary (counts and owners), next to the description the poller already reads.
- The simulator's routers run the mini image's board and revision (`dlink,dwr-921-c3-uboot`, `r35692-b8bffeefdf`), so e2e matches them to the mini image.

## Review Focus

1. A malformed or hostile image (a truncated squashfs, a `bytes_used` past the end, names with `../`, `$(…)` or a newline, a link loop, a non-UTF-8 package database): refused with its message or shown as text; never read past 64 MiB, never run, never put into a command (Task 2 `test_truncated_squashfs_refused`, Task 4 `test_hostile_entries_are_data`).
2. Overlay names with spaces, quotes, `$(…)` or a newline: the listing keeps them as data (a name with a newline is skipped and counted: "1 name could not be read"); Copy refuses any path outside `^/[A-Za-z0-9._/+@:=,-]{1,255}$` (Task 8 `test_overlay_names_with_shell_characters`, Task 11 `test_copy_refuses_unsafe_path`).
3. A flash that fails before `sysupgrade` starts (upload breaks off, the router's sha256 differs, `validate_firmware_image` says invalid, Bench Guard goes live during the upload): the partial file is removed, nothing is armed, the router is as it was and the job says why (Task 16 `test_failed_upload_removes_the_partial_file`, `test_validate_refusal_flashes_nothing`, `test_run_starting_during_upload_stops_before_sysupgrade`).
4. The router comes back on its old revision (stage 2 refused and it rebooted), or another router answers at its address, or nothing answers for 10 minutes: never "Flashed" (Task 16 `test_old_revision_after_reboot_is_not_success`, `test_other_board_at_the_address_is_not_success`, `test_no_answer_in_ten_minutes`).
5. An image for another board, or an image file changed on disk after import: refused before anything is sent (Task 15 `test_image_for_another_board_refused`, `test_image_changed_on_disk_refused`).
