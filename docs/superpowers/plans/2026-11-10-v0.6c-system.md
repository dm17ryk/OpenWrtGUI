# OpenWrtGUI v0.6c System (Access, LEDs, mount points, restore, reset) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The rest of the System screen (spec 7.11, second half): router password and password policy, SSH access, SSH keys, HTTP(S) access, repository keys (read-only), LEDs, mount points (read-only), the files kept in a backup, restore and reset to defaults, plus the seven v0.6b deferred minors. After this plan every LuCI System and Status page on the bench image opens natively except Mount points' fstab editing (D8), and 0.6.0 can be released.

**Architecture:** New modules beside v0.6b's in `system/`: `access.py` (dropbear, uhttpd, the rpcd password policy, the password), `sshkeys.py`, `leds.py`, `mounts.py`, `archive.py` (local checks of a backup archive) and `restore.py` (restore and reset jobs on top of `reboot.py`). A new `AccessService` serves the Access, LEDs and Mount points tabs so that `system/service.py` (524 lines) stays well under 800; restore, reset, import and the kept-files list go on `SystemService` next to the reboot job they share. Writes use the paths the app already has: uci through `net_plan` and `ApplyRunner.run_planned` (plain apply for uhttpd, LEDs and the policy; the v0.3 rpcd rollback for dropbear, extended here to follow a new SSH port), files through `write_file`'s heredoc, the password on stdin through `run_audited(..., stdin=)` as the wizard's `passwd root`, the archive through `run_audited_upload`, and the reboot and `firstboot` through `arm_command` and the come-back wait. The LuCI bridge learns to speak TLS to the router's loopback when HTTP redirects to HTTPS.

**Tech Stack:** as v0.6b (Python 3.13, FastAPI, asyncssh, pydantic 2; React 19, TypeScript, Vite, TanStack Query, vitest, Playwright). No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-03-openwrt-gui-design.md`: section 6 (safety, own path), 7.11 System (Access; LED configuration, mount points; Backup and firmware: restore, reset to defaults), 8 (System › Administration, Mount points, LED configuration, Backup / Flash firmware), 11 (testing), 13 (O20 is new). Follows `docs/superpowers/plans/2026-11-09-v0.6b-system.md`; its D1-D12 stand. LuCI's own pages for these views (luci-mod-system on AP2's SNAPSHOT r35692) were read upstream on 2026-11-10: `system/password.js`, `pwpolicy.js`, `dropbear.js`, `sshkeys.js`, `uhttpd.js`, `repokeys.js`, `leds.js` with `led-trigger/*.js`, `mounts.js` and `flash.js`.

## Review Focus

1. The app's own way in: disabling or removing the app's dropbear instance, moving it to an interface that does not hold the router's address, removing the app's key line, a new port nothing answers on, or a uhttpd listen list without loopback. Each is refused with the reason, or rolled back by the router, and the app is never left locked out (Task 6 `test_a_new_port_that_does_not_answer_rolls_back`, Task 9 `test_the_apps_ssh_path_is_kept`, Task 10 `test_the_apps_key_cannot_be_removed`, Task 11 `test_luci_off_the_network_keeps_loopback`).
2. A backup that is not this router's or is malformed: another router's host key, a different LAN address, no app key line, a member `../etc/passwd` or `/etc/shadow`, a symlink, 50 MiB, not gzip. Each is refused before a byte is sent, with the reason, and an imported file that fails is not kept (Task 4 `test_archive_refusals`, `test_restore_refusals`; Task 13 `test_import_listed_and_refused`; Task 14 `test_restore_refuses_another_routers_backup`).
3. Passwords that would break or leak: empty, with a newline, 129 characters, failing an enabled policy. Each is refused, and the password appears in no audit line, plan line, result, log or exception text (Task 8 `test_password_refusals`, `test_password_never_leaves_the_stdin`).
4. LuCI pages after an HTTP(S) change: with the redirect on, or LuCI off the network, a LuCI page in the app still opens. A custom listen list is shown and kept (Task 11 `test_the_bridge_follows_redirect_https`, `test_a_custom_listen_list_is_kept`).
5. A reset or restore started at the wrong moment: without the tick, with a wrong typed name, during a run, or while a reboot job runs. It is refused (409/422/423) with nothing sent. A reset that never takes the router down ends "not reset" with no marker (Task 14 `test_restore_while_a_reboot_runs`, Task 15 `test_reset_needs_the_router_alone`, `test_reset_that_does_not_go_down`).

## Rules (the decisions the code must follow)

- Dropbear flags read `on`/`1` as true and `off`/`0` as false; when absent they take LuCI's defaults (enable 1, Port 22, PasswordAuth on, RootPasswordAuth on, GatewayPorts off). A changed flag is written in the style its option already uses (`on`/`off` when the current value is one of those, else `1`/`0`); unchanged options are not written.
- The router's address interface is the one in `ubus call network.interface dump` whose `ipv4-address` holds `rec.host`.
- Key fingerprints are asyncssh's `get_fingerprint("sha256")` (`SHA256:...`), the same form as `AppKey.fingerprint`.
- A restore's files and their sha256 are computed on the PC from the archive in memory; the router's side is `sha256sum` of the same absolute paths.
- Every new write's audit `screen` is `"System"`. A new job kind shares `RebootJob` and the one-job-per-router rule (409).
