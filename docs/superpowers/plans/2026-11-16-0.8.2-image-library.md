# Image library (0.8.2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app finds a router's exact firmware build in the releases of `dm17ryk/openwrt`, downloads it on one
click and imports it, and this ships as OpenWrtGUI 0.8.2.

**Architecture:** A new `src/openwrtgui/images/library.py` reads the public releases API anonymously (as the
updater does), turns each release's OpenWrt `profiles.json` into catalog entries, caches them, and downloads one
image into memory. It then imports the image through the existing `ProfileStore.import_image`. Three endpoints
under `/api/images/library` feed a library line on Discovery's Image card and an **Image library** card in
Settings. In simulator mode the GitHub stand-in serves a fake firmware release built around
`tests/fixtures/images/mini-r35692.bin`. The release branch is cut from the `v0.8.1` tag, gets these commits
cherry-picked, then the version bump.

**Tech Stack:** Python 3.13, FastAPI, pydantic v2, httpx (`MockTransport` in tests), pytest; React, TypeScript,
TanStack Query, vitest, Playwright; uv and npm.

**Spec:** `docs/superpowers/specs/2026-11-16-image-library-design.md` (approved by Dmitry 2026-11-16, e7ea8d2).

## Global Constraints

- Branch `feat/image-library` in worktree `.claude/worktrees/image-library`, based on master 3852995. Local only:
  no push, PR, tag or release without Dmitry's own go.
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- The repository is fixed in code: `RELEASES_URL = "https://api.github.com/repos/dm17ryk/openwrt/releases"`, read
  with `params={"per_page": 100}` and the updater's headers
  (`Accept: application/vnd.github+json`, `User-Agent: OpenWrtGUI/{APP_VERSION}`).
- `profiles.json` at most 1 MiB (`MAX_PROFILES = 2**20`). An image at most `MAX_IMAGE` (64 MB, from
  `openwrtgui.images.sysupgrade`) and never more than its catalog `size`.
- Catalog cache: 600 s for a good read, 60 s for a failed one; Refresh bypasses both.
- Nothing is downloaded without a click. Looking up and downloading never touch a router, take no write lock and
  do not wait for Bench Guard.
- The Discovery read (`GET /api/routers/{id}/discovery`) never asks GitHub.
- Simulator mode and every test stay offline: GitHub is `simulator.sim_http_client` or an `httpx.MockTransport`.
- Exact texts (backend error `detail`s and screen text):
  - unreachable: `The image library on GitHub could not be reached: {reason}.`
  - rate limit: `GitHub's limit for anonymous reads is reached; try again after {HH:MM}.` (local time of
    `X-RateLimit-Reset`)
  - hash mismatch: `{image_name} does not match its release's profiles.json; nothing was imported.`
  - too large: `{image_name} is larger than its release says; nothing was imported.`
  - wrong build: `{image_name} is for {board} {revision}, not {entry board} {entry revision} as its release says;
    nothing was imported.`
  - busy: `{image_name} is already downloading.`
  - unknown: `No image {sha256[:12]} in the image library` (HTTP 404)
  - Discovery: `Looking in the image library…`; `The image library has no build for {board} {revision}.`;
    `Image library: {title}, {revision}, {size}, release {release_name}`; button `Download and import`, busy
    `Downloading {size}…`; others: `1 other build of this revision is listed in Settings › Images; Check firmware
    tells whether the router runs the one you downloaded.` (plural: `{n} other builds … are listed …`)
  - skipped: `1 release could not be read` / `{n} releases could not be read`
- Sizes on screen use the existing `megabytes()` of `frontend/src/screens/ImagesSection.tsx` (export it). It counts
  MiB, so 11,272,478 bytes shows as `10.8 MB`, not the spec sketch's 11.3 MB. *(Ruling: one size format in the
  app.)*
- Version for the release: 0.8.2. Master stays 1.0.0-dev.
- The v0.4 session is executing v1.0d (the manual) on `feat/v1.0d-manual-release` from the same master. Both
  branches edit `docs/manual/Discovery.md`, `docs/manual/Settings.md` and `CHANGELOG.md`; whichever PR merges
  second rebases.

## Review Focus

1. **GitHub's download redirect.** `browser_download_url` answers 302 to `objects.githubusercontent.com`; the
   download must follow it, which works only with a client made with `follow_redirects=True` (the real factory).
   Test: `test_download_follows_a_redirect` (Task 3).
2. **A body larger than the catalog says, with no Content-Length.** The cap must count bytes as they arrive.
   Test: `test_download_without_content_length_is_capped_by_the_catalog_size` (Task 3).
3. **Discovery and Settings open at once.** Two reads in flight must make one releases request.
   Test: `test_concurrent_reads_share_one_request` (Task 3).
4. **A release with no `profiles.json`** (an older or hand-made release) is simply not in the library and is not
   counted as unreadable. Test: `test_a_release_without_profiles_json_is_left_out_quietly` (Task 2).
5. **A download right after the app starts** (empty cache) must read the catalog first, not answer 404.
   Test: `test_download_reads_the_catalog_when_none_is_cached` (Task 3).

      5's test patches;
    - `async read(self, force: bool = False) -> LibraryRead`;
    - `async download(self, sha256: str) -> Profile`. It raises `KeyError` for an unknown SHA-256 and
      `ValueError` for everything else.
  - `CACHE_SECONDS = 600`, `ERROR_CACHE_SECONDS = 60`.

- [ ] **Step 3: Implement**

- **`Profile` and `import_image`:** `origin` goes on `Profile`. `import_image` builds the profile, checks
  `expect`, sets `origin` with `model_copy`, then stores as today.
- **`ImageLibrary.read`:**
  - holds an `asyncio.Lock`, so concurrent callers wait for one fetch;
  - a `LibraryError` becomes `LibraryRead(error=…)`, keeping the last good entries;
  - the cache age is measured with `clock`.
- **`ImageLibrary.download`:**
  1. Find the entry in `read()`.
  2. Refuse a SHA-256 that is already imported.
  3. Mark it busy in a `set`.
  4. Stream with the factory's client, counting bytes against `min(entry.size, MAX_IMAGE)`.
  5. Compare the SHA-256.
  6. Call `asyncio.to_thread(profiles.import_image, data, entry.image_name, clock(),
     origin=entry.release_url, expect=(entry.board, entry.revision))`.

  The busy mark is always cleared at the end.
