# v1.1b: Rate Statistics, App Key Rotation and the 1.1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** RF live shows which rates reach a station (minstrel `rc_stats_csv`), Settings can rotate the app's SSH
key router by router, one AP2 window proves both plus LTE Recover, and 1.1.0 is released.

**Architecture:**
- **Rates:** a parser for the kernel's `rc_stats_csv` (`rf/rates.py`), read by `RfSampler.rates` for the selected
  station when the RF screen asks over its WebSocket. The rates card asks only while it is open. The simulator
  serves rates for its station.
- **Key rotation:** an `AppKeyRing` (`store/keys.py`) holds the current key and, during a rotation, the next one.
  Every connection offers both. A `KeyRotation` job (`onboard/rotate.py`, modelled on `LteRecover`) moves each
  router in three steps: add the new line, prove a login with the new key only, remove the old line. When every
  router has moved, the next key replaces the current one and the old private key is gone.
- **Window and release:** hardware tests for the three proofs, run in one AP2 window, then the release PR, the tag
  and the start of 1.2, each on Dmitry's go.

**Tech Stack:** Python 3.13, FastAPI, pydantic, asyncio, asyncssh, pytest; React + TypeScript, TanStack Query,
Vitest, Playwright.

**Spec:**
- `docs/superpowers/specs/2026-11-03-openwrt-gui-design.md`, 7.3 ("Which rates reach the station": minstrel
  `rc_stats`, attempts, success %, in-use rate) and 7.12 ("App SSH key: fingerprint, export public key, rotate
  (re-deploys to every router, then removes the old key)").
- `docs/superpowers/plans/2026-11-17-1.x-inventory-and-split.md`, decisions D7-D10, which Dmitry answered "All
  recommended" (2026-11-17). D7: rates for the selected station only, every 5 s, only while the rates table is
  open. D8: per router, add the new key, prove a login with it over a new connection, remove the old key's exact
  line; the old private key is kept until every stored router has moved; a router that is off or fails stays on
  the old key, listed with Retry; other `authorized_keys` lines are never touched; refused during a harness run;
  audited. D9: one AP2 window. D10: Native, then a fresh reviewer on the most capable model, plus a security
  review of key rotation.
- Dmitry, 2026-11-18: "1.1.0 with 1.1b". LTE Recover (PR #82, merged as cba02a0) ships in 1.1.0, and its AP2
  proof (`docs/superpowers/plans/2026-11-17-lte-recover.md`, Task 13) joins this plan's window.

## Global Constraints

- **Test first** (AGENTS.md): every change starts with a test that fails before it.
- **No router access** except Task 11, which needs Dmitry's own OK in the orchestrator at the time, Bench Guard
  clear, and the txctl session told first. AP2 (192.168.1.2) only, never AP1 or AP3, not even to read. Agents never
  type router passwords. SSH host keys are never accepted on trust.
- **Writes** go through `run_audited` (`guard/writes.py`) under `pool.write_lock(router_id)` and are refused during a
  harness run (`GuardLocked`, 423). **Reads** from the background use `t.run`, and every new read passes
  `is_read_only_command` (`guard/readonly.py`).
- **The app's private keys** never leave the data folder, are never logged or audited, and a new private key file
  gets `restrict_to_user` before anything uses it.
- **`authorized_keys`:** only lines exactly equal to the old app key's public line are removed. Every other line
  stays byte for byte. The new key is proven before the old line goes, and the remove command itself refuses to run
  when the new line is missing.
- **The old private key** stays on disk until every stored router that logs in with the app key has moved.
- **Station MACs** from the browser are checked (`checked_mac`) before they go into a command.
- **Public repo:** no real keys, MACs, SSIDs, IMEIs or names in fixtures, tests or docs. Tests make their keys in
  `tmp_path`. Recordings go through the recorder's `sanitize`.
- **The UI words** below are the plan's own. Tests use them verbatim.
- **Nothing is pushed** without Dmitry's go. Branches are never deleted, local or remote. Never force-push.

## Review Focus

1. **A router that is off during a rotation.** It ends "failed" with "<name> did not answer: it stays on the old
   key". The others move. The job ends "pending", the old private key is still on disk, and Retry moves it once it
   answers. Test in Task 6.
2. **The app restarts in the middle of a rotation** (`rotation.json` and the next key on disk). Every router still
   logs in: moved ones with the new key, the rest with the old one. Start continues with the routers not yet moved.
   Tests in Tasks 4 and 6.
3. **An `authorized_keys` with CRLF lines, comments, an options-prefixed copy of the old key** (`no-pty
   ssh-ed25519 … openwrtgui@pc`) **and the old line twice.** Only the exact old lines are removed; the rest are
   byte-identical. Test in Task 5.
4. **A hostile or odd station MAC in the rates message** (`../../x`, `; reboot`, upper case). Upper case is
   accepted and lower-cased; anything else gets an error frame and no command is sent. Test in Task 2.
5. **A strange `rc_stats_csv`:** lines with the wrong field count, an empty answer, a station that left (`cat`
   fails). Good lines are kept, an empty answer gives no rows, and a failed read says "No rate statistics from the
   router for this station". Tests in Tasks 1 and 2.

8. max throughput;
9. average throughput;
10. average probability;
11. retry count;
12. last success;
13. last attempts;
14. total successes;
15. total attempts;
16. ideal packets;
17. sample packets;
18. average A-MPDU length.

**Interfaces:**
- Produces, in `store/keys.py`:

  - `class AppKeyRing`:
    - `__init__(self, keys_dir: Path, comment: str | None = None) -> None`. It loads or creates the current key
      (`load_or_create_app_key`), loads the next key and `rotation.json` if a rotation is pending, and completes an
      interrupted finish (R6).
    - `current: AppKey` (property): the key routers log in with; the old one during a rotation.
    - `next: AppKey | None` (property).
    - `login_paths(self) -> list[Path]`: `[current]`, or `[current, next]` during a rotation (R4).
    - `fingerprints(self) -> frozenset[str]`: one, or both during a rotation.
    - `moved(self) -> frozenset[str]`: the router ids moved in this rotation.
    - `begin(self) -> AppKey`: makes the next key (ed25519, the same comment form, `restrict_to_user` on the

      `ValueError("A key rotation is already under way")` if one is pending.
    - `mark_moved(self, router_id: str) -> None`: written atomically (`write_atomic`).
    - `finish(self) -> AppKey`. In order:
      1. `os.replace` of the next private key onto `id_ed25519`;
      2. `id_ed25519.pub` rewritten from the new key;
      3. `id_ed25519.next.pub` deleted;
      4. `rotation.json` deleted.

      It returns the new current key. It raises `ValueError("No key rotation is under way")` when none is pending.

  - `AccessService.app_fingerprints(rec)` returns `keys.fingerprints()` for a router on the app key.
