# v1.0c Hardening II: performance and robustness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the slow reads fast, with each gain measured before and after. Keep a screen working when a live socket
drops or a component throws. Close the correctness and UX minors that v1.0b1 and v1.0b2 deferred.

**Architecture:**
- **Task 1 adds a read-budget test.** It pins how many SSH commands each read sends today. Each speed-up task lowers
  its own row first (RED), then makes the read meet it (GREEN). So every gain in this plan is a number a test holds.
- **Two small shared pieces:**
  - a per-read memo of identical reads (`transport/memo.py`, Task 6);
  - a live-socket hook with reconnect (`frontend/src/api/useLiveSocket.ts`, Task 9).
- **Everything else** is a local change in the module that owns the behaviour.

**Tech Stack:** Python 3.13, FastAPI, pydantic 2, asyncio, pytest (asyncio auto), ruff (line 110, `S` on), mypy
strict, React 19, TanStack Query, vitest, Playwright.

## Baseline at 108a89e (measured 2026-11-16, simulator, no router)

**How it was measured:**
- `build_context(..., simulator=tests/fixtures/sim)`, with `OPENWRTGUI_SIM_SEED=ap4,ap5`.
- Each GET was sent twice. **Cold** is the first read (it includes the router description and the network state).
  **Warm** is the second. A count is the `ReplayTransport.calls` added by that request.
- **Modelled seconds:**
  - every SSH command costs 0.05 s;
  - an AT exchange adds 2.0 s, because `microcom -t 2000` waits 2 s of silence after the modem's answer. v0.6a
    measured `GET /lte` at 6-12 s on AP2, which fits five exchanges;
  - a `uqmi` read adds 0.3 s.
- The counts are exact. The seconds are a model; D11 says how real AP2 numbers can be added later.

| Read | Cold | Warm | AT exchanges (warm) | Modelled warm | How often |
|---|---|---|---|---|---|
| `GET /lte` (ap1) | 30 | **15** | **5** | **11.65 s** (cold 18.4 s) | opening LTE, every refresh, after each action |
| `GET /faults` (ap1) | 34 | **19** | 0 | 0.95 s | opening Faults, after each arm and clear |
| `GET /firewall/iptables` (ap4) | 9 | **9** | 0 | 0.45 s | **every 10 s** while the tab is open |
| Two LuCI page lists at once, the description known, the facts cold (ap2) | 2 × 6 on a router | - | 0 | 0.6 s | menu and a bridge opened together. One cold list alone is 17: 11 to describe the router, 6 for the facts. The simulator answers without yielding, so it shows 6 either way (Task 4 proves it with a held transport) |
| Discovery Run --help preview (ap1, mini profile, router described) | 12 | **12** | 0 | 0.6 s | every preview; the apply reads again (13) |
| The status poller, per router per tick after the first | - | 7 (ap1), 5 (ap2) | 0 | 0.35 s | every 5 s, always |
| Regression rows: firewall 9, network 4, wifi 6, ports 10, system access 9 (warm, ap1) | | | | | |

**Where the time goes:**
- **`/lte`:** the five AT exchanges are AT+CGMI, AT+CGMM, AT+CGMR, AT+COPS? and AT+BMMODODR?. Three of them never
  change while the modem stays plugged in.
- **`/faults`:** it sends three reads twice: `cat /proc/net/arp`, `ubus call network.wireless status` and
  `ubus call luci-rpc getHostHints`.
- **`/iptables`:** one presence `ls`, then 2 programs × 4 tables.
- **Discovery:** each preview reads the whole Discovery state (12 commands) only to check that the path is a custom
  program.

**Targets (the budget rows after this plan):**
- **`/lte` warm:** 15 → 11 commands, 5 → 1 AT exchange; modelled 11.65 s → 2.25 s. That is 3.45 s without the
  overlap of D3.
- **`/iptables`:** 9 → 1 (0.45 s → 0.05 s per 10 s refresh).
- **Two LuCI page lists at once (facts cold):** 12 → 6 on a router. Task 4's held-transport test proves this, not the
  budget table. The router description read is shared through the poller in practice and stays out of scope.
- **Discovery preview:** 12 → 2; apply 13 → 3.
- **`/faults` warm:** 19 → 16.

## Global Constraints

- **Test first:** a change without a test that failed before it is not done (AGENTS.md).
- **Reads:**
  - background reads use `t.run` directly, never `run_audited`;
  - every read constant passes `is_read_only_command`. Task 3 adds one constant (`IPT_STATE`), which goes into
    `readonly._EXACT`;
  - the recorded AP2 commands (`tests/fixtures/ap2/*.json`) replay by exact string, so no existing command text
    changes.
- **Writes:**
  - every write goes through `ApplyRunner.run_planned` or `run_audited`;
  - Bench Guard refuses writes during a harness run (`GuardLocked`, 423);
  - this plan adds no write command. Task 10 puts the existing `SCAN_DEL` at the front of a plan; Task 11 reorders the
    include plan's existing lines.
- **SSH concurrency:** reads on one pooled connection may already run at once (the poller, a screen and the RF
  sampler do). Task 2 runs two groups of reads at once inside one request. Nothing else adds concurrency.
- **No router access:** nothing in this plan runs on AP2 or any bench router (D11).
- **GitHub:** nothing is pushed and no GitHub object is created without Dmitry's explicit go. Branches are never
  deleted.
- **Public repo:** no real keys, passwords, names, neighbour MACs or SSIDs in fixtures, tests or docs. Test MACs are
  `02:00:00:…` or the simulator's own.
- **Scripts** run inside `D:\Essence_SC` or `C:\Essence_SC` (SentinelOne).
- **Style:**
  - ruff line length 110, ruff `S` on, mypy strict, functions under 50 lines; oxlint and `tsc -b` clean.
  - Source and test comments name no person: they cite "the final review", a ledger or a date.
- **API model changes:** after one, run `uv run python tools/dump_openapi.py && cd frontend && npm run gen:api`, and
  commit `frontend/src/api/schema.ts` with it (Task 7 adds a field).
- **CHANGELOG:** one line per task under `[Unreleased]`: `### Changed` for Tasks 2-7, `### Fixed` for the rest.
- **pytest groups:** `tests/unit/wifi` and `tests/unit/api` clash when mixed in one pytest call. Run them separately;
  the full suite from the root is fine.
- **The gate**, before the review and after the fix pass:
  - In a fresh worktree, first run `uv sync --extra dev` (pytest, ruff and mypy are dev extras) and `npm ci` in
    `frontend`.
  - `uv run ruff check . && uv run ruff format --check . && uv run mypy`
  - `uv run pytest`: everything passes; coverage stays at 95% or more.
  - The schema check: dump, `gen:api`, then `git diff --exit-code frontend/src/api/schema.ts`.
  - `cd frontend && npm run lint && npm run build && npm test && npm run e2e`

## Decisions

| # | Decision |
|---|---|
| D1 | **Scope: one plan of 13 tasks, "performance and robustness".** Performance is six measured speed-ups (Tasks 2-7). Robustness is the error boundary, the 500 handler and the socket reconnects (Tasks 8-9). The rest is the correctness minors that v1.0b1 and v1.0b2 deferred, and the UX minors a person meets in normal use (Tasks 10-13). The cosmetic and rare UX minors, the tooling items, the poller and the capture-across-rollback change go to 1.x; the installer test goes to v1.0d. *The other choice:* performance only (Tasks 1-7). Tasks 8-13 would then move to 1.x, and v1.0 would ship with sockets that need a re-open and a blank screen on a thrown error. |
| D2 | **The modem's identity is kept per connection** (#25). The manufacturer, model, firmware and mode order (AT+BMMODODR?) are read once per connection with the AT port, as the port already is. **Read again after:** any AT write from the console, a Reboot modem action, a new connection, or a port that stops answering. The operator (AT+COPS?) is read every time. *The other choice:* read the mode order every time (2 AT exchanges per read, about 4.3 s modelled). A mode order changed outside the app, from the terminal with `microcom`, shows only after a new connection. |
| D3 | **The LTE reads overlap the AT exchange.** The uqmi and netifd reads run at the same time as the AT exchange on the same SSH connection. They use different devices (`/dev/cdc-wdm0` and `/dev/ttyUSB*`), and the AT lock still covers the whole read. This saves about 1.2 s per read. *The other choice:* keep them in sequence (3.45 s modelled instead of 2.25 s). |
| D4 | **`microcom -t 2000` stays.** A shorter idle timeout would cut each AT exchange, but the BM806C's answer times were never measured, and a cut-off answer reads as "no answer". Changing it needs an AP2 proof, so it goes to 1.x. |
| D5 | **Faults asks each identical read once per request** (memo). The status poller (5-7 commands per router every 5 s), a single-exec poller read and concurrent reads in other screens go to 1.x. They mean more change to every read function, and nothing measured here says a person waits on them. |
| D6 | **A Wireshark that falls behind loses packets on its own view only.** The pipe is fed from a thread through a bounded queue of 64 chunks (64 KiB each, up to 4 MiB). Chunks that do not fit are counted, and the capture card says "Wireshark fell behind: 3.1 MB not shown; the capture goes on". When Wireshark is closed, the capture ends with today's message. File captures do not change. *The other choice:* end the capture when Wireshark falls behind. |
| D7 | **Live sockets reconnect by themselves.** This covers LTE, RF live and System status. On an unexpected close the screen says "Lost the connection to OpenWrtGUI; reconnecting (attempt N)" and tries again after 1, 2, 4, 8 and 15 s, then every 15 s while the screen stays open. A close code of 4000 or more is the app's own refusal (4404: unknown router), so it ends the socket and shows its reason. Leaving the screen stops the retries. |
| D8 | **An unexpected error answers 500 with a plain message:** "Unexpected error in OpenWrtGUI (RuntimeError). The details are in the app log." The traceback goes to the log only. **In the frontend:** each screen is inside an error boundary. A screen that throws shows "This screen hit an error: <message>. The other screens still work." with Try again, while the header, the guard banner and the router rail stay. Moving to another screen clears it. |
| D9 | **Exact non-secret names** (the v1.0b1 final review). `igmp_snooping`, `ping`, `mapping`, `passive` and `key_type` join `_SHOWN`. The substring rule stays as it is, because third-party options run words together (`apikey`, `totpsecret`). A name nobody has reviewed is still hidden. *The other choice:* match whole name segments. That shows the four names, but hides nothing in `totpsecret`. |
| D10 | **UX minors in v1.0c:** #9, #13, #32, #43 (Task 12); #19, #67 and the remove-router button (Task 13). **To 1.x:** #4, #6, #21, #27, #30, #35, #36, #50, #52, and #3 (a capture across a rollback: size M, it needs its own connection). |
| D11 | **No AP2 window.** Every gain is a command count on the simulator, held by the budget test. The overlap is proven by a test that deadlocks without it. *Optional, after the merge, with Dmitry's OK at the time, the txctl session told and Bench Guard clear:* a read-only timing run on AP2. It would time `GET /lte` three times, cold and warm, with the AT queries and uqmi reads the screen already sends and no writes, about 10 minutes, so the PR and the manual can give real seconds. |
| D12 | **Execution: Native, then one fresh reviewer on the most capable model** (as v1.0a2 to v1.0b2). The tasks share little (pre-flight below). Each speed-up carries its own budget row. A mistake costs a slow or stale read, not a router: no write path changes. |

## Review Focus

1. **A kept modem identity that outlives its modem.** A modem swapped or re-enumerated, a firmware change, the
   reboot action, an AT write from the console: the next read must show the new identity. Task 2 tests a write, a
   new connection and a silent port.
2. **A connection that drops in the middle of the overlapped LTE read.** Both halves must end, the AT lock must be
   released, and no identity may be kept. The next read starts clean. Task 2 tests a `TransportError` in the AT half.
3. **The LuCI facts read that two callers share when it fails.** Both get UNCHECKED, nobody hangs, and the next call
   reads again. A write during the read must not let it be kept. Task 4 tests both.
4. **One table of the single iptables read that fails** (no ip6tables, a missing table module). That table shows its
   error and the others still show, as today. Task 3 tests an absent program and a table that exits 1.
5. **A live socket closed on purpose, or a screen left during a retry.** A 4404 close does not reconnect. A screen
   left while waiting to retry opens no new socket. Task 9 tests both.

WARM = {
    ("ap1", "/api/routers/ap1/lte"): 15,
    ("ap1", "/api/routers/ap1/faults"): 19,
    ("ap4", "/api/routers/ap4/firewall/iptables"): 9,
    ("ap1", "/api/routers/ap1/firewall"): 9,
    ("ap1", "/api/routers/ap1/network"): 4,
    ("ap1", "/api/routers/ap1/wifi"): 6,
    ("ap1", "/api/routers/ap1/ports"): 10,
    ("ap1", "/api/routers/ap1/system/access"): 9,
}
AT_WARM = {("ap1", "/api/routers/ap1/lte"): 5}
HELP_PREVIEW = 12  # Discovery Run --help preview on ap1 with the mini image's profile, the router described
POLL_TICK = 7  # one status tick on ap1, after the first

@pytest.mark.parametrize("key", list(WARM))
async def test_a_warm_read_stays_within_its_budget(seeded: httpx.AsyncClient, seeded_ctx: AppContext, key) -> None:
    router, path = key
    await seeded.get(path)
    sent = await count_read(seeded, seeded_ctx, router, "GET", path)
    assert len(sent) <= WARM[key], sent

@pytest.mark.parametrize("key", list(AT_WARM))
async def test_a_warm_read_asks_the_modem_within_its_budget(seeded, seeded_ctx, key) -> None:
    router, path = key
    await seeded.get(path)
    assert at_exchanges(await count_read(seeded, seeded_ctx, router, "GET", path)) <= AT_WARM[key]

async def test_a_run_help_preview_stays_within_its_budget(seeded, seeded_ctx) -> None:

async def test_a_status_tick_stays_within_its_budget(seeded_ctx) -> None:
