# v1.2b: The Active Tool Pages and the 1.2.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** The Tools screen gains the pages that send traffic or change the router: **Throughput** (iperf3),
**Traffic generator** (socat), **Station management** (hostapd), and a **SIP ALG switch** on Connections. One AP2
window proves them, and 1.2.0 is released.

**Architecture:**
- **Tool sessions:** iperf3 and socat's Listen run on the router for a while and stream their output back. A
  new engine, `ToolSessions`, runs each one as a stream on its own SSH connection, the way Faults' capture
  does. Its command prints its own pid first and `exec`s the tool under `timeout -s KILL`. **Stop** sends
  `kill <pid>`. The engine stops a session when Bench Guard goes live, at its time limit, or when the router
  goes away.
- **One-shot writes:** socat's **Send** and the three hostapd actions are single audited commands with an
  exact preview, like the existing Wi-Fi station actions. A hostapd action that expects the station's answer
  first starts a 10 s `ubus subscribe` on its own connection.
- **SIP ALG switch:** a firewall uci write through the existing `ApplyRunner`, with the 60 s rollback. It is
  proven by effect in `nft -a list ruleset`.
- **Pages:** three new Tools tabs (after Connections). Connections' SIP ALG card gains the switch. The
  Discovery chips link to the new tabs.

**Tech Stack:** Python 3.13, FastAPI, pydantic, asyncio, pytest; React + TypeScript, TanStack Query, Vitest,
Playwright.

**Spec:**
- `docs/superpowers/specs/2026-11-03-openwrt-gui-design.md`, 7.8 "Phase 2" (D17). The tool pages are
  Throughput, Air survey, Station management, Traffic generator, Port statistics, and Connections ("`conntrack`,
  SIP ALG toggle").
- `docs/superpowers/plans/2026-11-19-v1.2a-capability-chips-and-read-pages.md`, "1.2b: decisions to answer
  before its plan": B1-B6. Dmitry answered "All recommended" on 2026-11-19, and "Yes, write 1.2b" on 2026-11-20.
  The recommended answers, in short:
  - B1: iperf3 runs on the router, as client or one-shot server; no `iperf3.exe` is bundled.
  - B2: traffic pages count as writes: refused during a harness run, stopped if a run starts.
  - B3: socat Listen and Send, at most 300 s each.
  - B4: SIP ALG through the firewall's uci write with the 60 s rollback (`auto_helper '0'` plus the other
    helpers); switching back restores the zone.
  - B5: Station management over hostapd's ubus: BSS transition request, neighbour report, beacon report request.
  - B6: one AP2 window of about 45 minutes.
- v1.2a merged as PR #96 (master 3fd17ad). Its hand-over asks this window to prove the mt7620's 16-bit packet

## Review Focus

1. **Hostile input reaching a shell.** Each must be refused with the field's rule, never reach a command, and
   never pass a socat option. Test in Tasks 2 and 3:
   - hosts: `x; reboot`, `$(id)`, `-p`, `a,b`, `a:b`, a space, 254 characters;
   - a text line with `'`, `$(id)`, a newline or a non-ASCII character;
   - ports 0 and 65536.
2. **A session that ends badly:**
   - the router drops mid-stream;
   - iperf3 reports `{"event":"error",...}`;
   - the `kill` fails;
   - Stop is pressed twice;
   - the router's `timeout` ends the tool (exit 137).

   Each ends with `running == False`, one clear `error` (or none, for the limit), and no second `kill`. Test in
   Tasks 1 and 2.
3. **Bench Guard goes live mid-session:** the session stops within two polls. The `kill` is sent although the
   guard is live, and the error reads "Stopped by Bench Guard: <reason>". Test in Task 1.
4. **SIP switch on an unusual zone:**
   - a zone with an explicit list that has `sip`;
   - a user's `auto_helper '0'` list without `sip`;
   - a masquerading zone with no helper chain;
   - a router without fw4 ("This router has no fw4 ruleset, so SIP ALG cannot be switched here.").

   Test in Task 4.
5. **hostapd says no:** "Not supported", "Not found", a station that left between the read and the request, or no
   notification in 10 s ("No answer from the station in 10 s."). Each gives its message and leaves nothing
   running. Test in Task 5.
