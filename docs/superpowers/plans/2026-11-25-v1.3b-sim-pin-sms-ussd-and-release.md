# v1.3b: SIM PIN, SMS and USSD, then 1.3.0, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** The LTE screen shows the SIM's PIN state and takes a PIN when the SIM asks for one, lists, reads,
deletes and sends SMS, and sends a USSD code and shows the network's reply. Then 1.3.0 is released.

**Architecture:**
- **One new service, `ModemService`** (`src/openwrtgui/lte/modem.py`), beside `LteService`. It borrows
  LteService's connection, modem device, AT port, AT lock and a new `write_slot` (the reservation the AT console
  and the actions already make). `GET /lte` does not change: its read count is pinned since v1.0c.
- **SIM and SMS go over uqmi** (D1, D2): `--uim-get-sim-state` / `--get-pin-status`, `--verify-pin1`,
  `--list-messages`, `--get-message`, `--delete-message`, `--send-message`. uqmi decodes the PDUs.
- **USSD goes over AT** (D3): `AT+CUSD=1,"<code>",15` through microcom with a 30 s silence wait, killed at
  35 s, instead of the console's 2 s.
- **Pure parsers** in `lte/sim.py`, `lte/sms.py`, `lte/ussd.py`. The simulator's `SimModem` gains a SIM, two
  message stores and USSD replies.
- **Three cards** on the LTE screen: SIM, SMS, USSD.
- **One AP2 window**, about 30 minutes (D6). It records shapes only, never content.

**Tech Stack:** Python 3.13, FastAPI, pydantic, asyncio, pytest; React + TypeScript, react-query, Vitest,
Playwright.

## Decisions this plan makes (for Dmitry's review; each is a ruling, not a question)

| # | Decision | Cost if wrong |
|---|---|---|
| E1 | **SIM, SMS and USSD live in `ModemService` and their own API module**, `api/lte_modem_api.py`, under the same prefix `/api/routers/{router_id}/lte`. `GET /lte` keeps its pinned read count; each card reads its own endpoint when it opens. | One more request per card. |
| E2 | **SIM state:** `--uim-get-sim-state` first, because it also gives the card state. `--get-pin-status` is the fallback when that fails. "PIN needed" means `pin1_status` is `not_verified`, or the card state is `pin1_or_upin_pin_required`. "Blocked" means `pin1_status` is `blocked` or `permanently_blocked`, or the card state is `puk1_or_upin_puk_required` or `pin1_blocked`. Both answers' tries are read: `unblock` in one and `unlock` in the other. | A state name this firmware never sends shows as "unknown". |
| E3 | **Enter PIN refuses on the last try.** With one try left, a wrong PIN leaves the SIM needing its PUK, which the app does not offer (D1). The card then says to enter the PIN in a phone or the D-Link UI. | The last try is made outside the app. |
| E4 | **The PIN's path.** `--verify-pin1 <pin>` (5000 ms). It needs Bench Guard clear, Recover not running and the LTE write slot. It is audited with `secrets=(pin,)`, and the audit's new uqmi rule hides it as well. It is never stored, logged or returned. pydantic `Field(repr=False)`. The UI clears the field after every try. SECURITY.md says the PIN is briefly on uqmi's command line on the router. | A local `ps` on the router can see it for about a second. |
| E5 | **SMS reads.** The list (`--list-messages --storage sim\|me`) is a read: not audited, allowed during a harness run, and in the read-only grammar (D4). Storage use and capacity come from `AT+CPMS?` with the list. `--get-message` runs only when the person asks. It is audited with the command only, never the text, and runs during a harness run, as AT queries do. | A message is marked read during a run. |
| E6 | **SMS writes** (delete and send) use a preview, its digest and Apply, like the LTE actions. They need Bench Guard clear and the write slot. Send takes 1 to 160 characters of the GSM 7-bit basic set; uqmi encodes 7-bit only. The target is `\+?[0-9]{3,15}`. The audit hides the text and keeps the number (the audit stays on this PC). | No Hebrew or emoji SMS from the app. |
| E7 | **Delete binds the list it was planned from.** The digest covers the storage and the ids. Apply reads the list again and answers 409 ("The message list changed; preview again") if the ids are not the ones previewed. | An index reused within those seconds is the remaining risk. AP2's SIM is full, so nothing new arrives there. |
| E8 | **USSD command:** `printf '%s\r' 'AT+CUSD=1,"<code>",15' \| timeout -s KILL 35 microcom -t 30000 -s 115200 <port>`, with a 45 s transport timeout. It holds the AT lock throughout, so the AT console and the screen's modem read wait. A code is `[*#][0-9*#]{1,30}#`. | Every USSD takes up to 35 s. A reply after 35 s is lost. |
| E9 | **The USSD session is closed by the app.** After a reply asking for more (`m` = 1), or after no reply, the app sends `AT+CUSD=2` through the 2 s AT path. Menus are not supported in 1.3b. | A menu USSD cannot go past its first screen. |
| E10 | **USSD text decoding** follows the data coding scheme (3GPP TS 23.038). UCS-2 arrives as hex and is decoded as UTF-16BE. 8-bit is shown as hex. Anything else is shown as the modem gave it. | A carrier's odd DCS shows hex. |
| E11 | **O2, the mode names:** the window reads `AT+BMMODODR=?`, a test query. A name is mapped only if the modem gives one. Otherwise O2 goes to the backlog, and ROADMAP and the spec drop "mode names" from v1.3 (Task 12). | O2 stays open. |
| E12 | **One write at a time.** SIM, SMS and USSD writes take `LteService.write_slot`, so they refuse (409) while Recover or an LTE action runs. Recover refuses while one of them runs, through `action_busy`. | None. |
| E13 | **The window (D6)** runs only what its options name, on AP2 only, with Dmitry's OK at the time. It writes shapes only: key names, value kinds, lengths, counts, `m` and DCS. It never writes a message's text, a number or a reply's text. The number for the optional SMS is passed on the command line at the time and never written. No Wi-Fi radio is involved. | A second window if a part fails. |

## Review Focus

1. **A PIN that leaks.** It could come back in an error text (uqmi echoing its arguments, an exception's `str`
   in a 500), the audit, a log, the react-query cache, or the field after a failed try. Expected: it appears
   nowhere but the one command sent. Tests in Task 4 (service and API) and Task 7 (card).
2. **The message list changes between preview and apply** (a message deleted from a phone, a new one arriving
   into ME storage). Expected: 409, nothing deleted. Test in Task 5.
3. **A USSD reply that is not plain:** UCS-2 hex, text with commas or quotes inside, an `m` of 2, 4 or 5, or no
   reply at all. Expected: decoded text or a clear status, and the session closed when E9 says. Tests in
   Tasks 2 and 6.
4. **A harness run or Recover around a write.** A run that starts during the 35 s USSD wait ends nothing: the
   command was sent before, and the reply comes back. A Recover start during that wait is refused (409).
   Tests in Task 6.
5. **SMS text outside the GSM 7-bit basic set** (é, €, `[`, Hebrew, an emoji) or over 160 characters.
   Expected: the rule's text before any preview, and nothing sent. Tests in Task 2 (rule) and Task 8 (card
   counter).
