# OpenWrtGUI v0.2 Wi-Fi and LuCI fallback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship OpenWrtGUI 0.2.0: a Wi-Fi screen per router (mode, channel, TX power, security, SSID; Apply with an exact preview, then proof on air), a stations table with Deauth and Block, an "All options" editor generated from the router's own option list, an RF live screen (radio and per-station RX/TX, charts, minstrel rates, CSV recording), and LuCI fallback pages that open any LuCI page inside the app without a password.

**Architecture:** New backend packages `wifi/` (pure compilers and parsers, then a service on top of an audited command runner), `rf/` (a 1 Hz sampler per router that runs only while a client watches, on its own WebSocket) and `luci_bridge/` (rpcd session over SSH, an SSH port forward, and a per-bridge loopback proxy that requires a bridge cookie and injects LuCI's session cookie). The simulator learns wireless state so e2e can apply and verify. The UI adds a per-router section list, the Wi-Fi and RF live screens and a LuCI tab; charts use uPlot.

**Tech Stack:** as v0.1 (Python 3.13, FastAPI, asyncssh, httpx, pydantic 2; React 19, TypeScript ~5.9, Vite, TanStack Query, react-router HashRouter, vitest, Playwright), plus `uplot` 1.6.32 (MIT).

**Spec:** `docs/superpowers/specs/2026-11-03-openwrt-gui-design.md` (approved 2026-11-03): sections 4 (LuCI fallback bridge), 5 (forms from typed options, known writers), 6 (safety), 7.2 Wi-Fi, 7.3 RF live, 7.14 LuCI pages, 8 (parity), 11 (testing), 13 (O4, O5, O6, O13). Mockups: `docs/design/canvas/project/WiFi.dc.html`, `RF.dc.html`, `LuCI.dc.html`, `Discovery.dc.html` (LuCI pages card).

## Wi-Fi rules (the decisions the code must follow)

Pure modes follow Dmitry's rule (2026-10-25): each mode uses only its own rates in both directions. The masks were proven on AP2 by `txlab_4b_rx.py` (2026-10-25): mac80211 refuses a bitrate mask without one basic rate of the BSS, so HT-only keeps the lowest basic rate 6. The b-only mask keeps all four CCK rates (the harness pins 11 for its own test reasons).

**Mode selection** → radio options (`wireless.<radio>`) and a runtime TX mask (`iw dev <if> set bitrates …`, re-applied after every reload the app makes):

| Selection | `htmode` | `noscan` | `legacy_rates` | `supported_rates` | `basic_rate` | TX mask arguments |
|---|---|---|---|---|---|---|
| Auto | board maximum (`HT40` when `board.json` allows 40 MHz, else `HT20`) | deleted | untouched | deleted | deleted | none (clears the mask) |
| ticked set S | `HT40` if n40 ∈ S, else `HT20` if n20 ∈ S, else `NOHT` | `1` if n40 ∈ S and n20 ∉ S, else deleted | `1` if b ∈ S else `0` | CCK if b ∈ S, then OFDM if g ∈ S; if neither: `6000 12000 24000` | `1000 2000` if b ∈ S, else `6000 12000 24000` | `legacy-2.4` + `1 2 5.5 11` if b + `6 9 12 18 24 36 48 54` if g, or `6` if neither; then `ht-mcs-2.4` + the phy's MCS indexes if n20 or n40 ∈ S |

CCK = `1000 2000 5500 11000`; OFDM = `6000 9000 12000 18000 24000 36000 48000 54000` (kb/s, ascending, space-separated). "All" is S = {b, g, n20, n40}. Empty S is refused: "Tick at least one mode, or choose Auto or All." Reading back: no `supported_rates`, `basic_rate` or `noscan` and `htmode` equal to the board maximum → Auto; values the table produces for some S → that S; anything else → `custom` ("Set outside the selector; see All options"). The lowest basic rate (the beacon rate) is 1.0 Mb/s when b ∈ S, or for Auto with `legacy_rates=1`; otherwise 6.0 Mb/s.

**Channel selection** → `channel`, `channels`, `disabled`:

| Selection | Writes |
|---|---|
| Auto | `channel=auto`, `channels` deleted, `disabled=0` |
| All | `channel=auto`, `channels='<lo>-<hi>'` over the allowed channels, `disabled=0` |
| None | `disabled=1` (radio parked; nothing else changes) |
| one channel N | `channel=N`, `channels` deleted, `disabled=0` |
| several | `channel=auto`, `channels='N1 N2 …'` ascending, `disabled=0` |

Allowed channels are `iwinfo freqlist` entries that are not `restricted`. Refusals: "Channel 14 is not allowed in country IL"; "Tick at least one channel, or choose Auto, All or None." Un-parking a radio whose SSID is on air on another known router adds the preview warning "<SSID> is already on air on <router name>. The bench rule is one radio on air per SSID."

**TX power**: Auto → `txpower` deleted; Fixed N → `txpower=N` (dBm), N in `iwinfo txpowerlist`. Refusal: "25 dBm is above this radio's maximum of 20 dBm"; Cap → "TX power cap is not available on this radio".

**Security and SSID** (`wireless.<iface section>`): Open → `encryption=none`, `key` deleted; WPA2-PSK → `psk2`; WPA3-SAE → `sae`; WPA2+WPA3 → `sae-mixed`. Refusals: "WPA3 needs SAE, which this router's hostapd does not have" (`getFeatures.hostapd.sae` false); "6 GHz allows only WPA3-SAE"; "A Wi-Fi key needs 8 to 63 characters, or 64 hex digits"; "An SSID is 1 to 32 bytes". An empty key keeps the current key; switching from Open to a PSK mode without a key is refused: "Enter a key for <SSID>".

**Only changes are written**: every compiled `set` whose value already equals the current uci value, and every `delete` of an absent option, is dropped. If nothing is left: "Nothing to apply: the router already has these settings."

**Apply** (one write, under the write lock):
1. Script (one exec, 60 s timeout, shown line by line): the `uci set …='…'` / `uci -q delete …` / `uci add_list …` lines (values single-quoted, `'` written as `'\''`), `uci commit wireless`, `wifi down <radio>; wifi up <radio>`.
2. Settle: `ubus call network.wireless status` every 1 s, up to 30 s, until the radio has `pending` false and `up` true (None: `up` false).
3. TX mask: `iw dev <ifname> set bitrates <args>` (args empty for Auto), where `<ifname>` is the radio's first interface with an `ifname` in the settled status. The preview shows the name when the radio is up now, otherwise `<AP interface of radio0>` with the note "the interface name is read after the radio comes up".
4. Verify (each a `Check`):

| Check | Passes when |
|---|---|
| radio | up with an AP interface (None: `iw dev` lists no interface on the radio's phy) |
| channel | `iw dev <if> info` channel equals N, or is in the ticked set (Auto/All: any allowed) |
| width | HT40 + noscan → 40 MHz; HT40 without noscan → 40 or 20 MHz; HT20 → 20 MHz; NOHT → 20 MHz "(no HT)" |
| TX power | Fixed N: actual within 1 dBm of N; Auto: actual is reported |
| TX mask | the `set bitrates` command exited 0 |
| beacon rate | `iw phy <phy> interface add owgmon0 type monitor && ip link set owgmon0 up`, then `timeout 5 tcpdump -i owgmon0 -e -n -c 5 -l 'type mgt subtype beacon and wlan addr2 <bssid>'`, then `ip link del owgmon0`: at least one beacon, all at the lowest basic rate |

For None only "radio" runs; the others are `not run: radio parked`. Every command of steps 1, 3 and 4 is audited (`screen="Wi-Fi"`; `source="user"` for step 1, `"app"` for 3–4); then one audit entry `command="verify <radio>"`, `exit_status=None`, `verify="pass"` or `"fail: <failed check names>"`.

**TX mask tracking**: after a successful mask command the service remembers `(router, ifname) → ifindex` (from `iw dev <if> info`). `WifiState` reports the mask as `active` when the interface's ifindex is unchanged, `missing` when the selection needs a mask and the ifindex differs or nothing was remembered (a reload by anyone recreates the interface), `none` for Auto.

**Station actions** (`ubus call hostapd.<ifname> del_client …`): Deauth → `{"addr": MAC, "ban_time": 0, "deauth": true, "reason": 3}`; Block for N s (N = 10…3600) → the same with `"ban_time": N * 1000`.

## Review Focus

1. Another program (a harness, LuCI, `wifi reload` by hand) reloads Wi-Fi after the app applied pure modes: the runtime TX mask is silently gone. The Wi-Fi screen must say "TX mask not active: the radio was reloaded since the last Apply. Apply again to restore it." (Task 5 test `test_mask_reported_missing_after_interface_recreated`; Task 10 test `shows the mask-missing note`).
2. The SSH connection drops, or Bench Guard goes live, between `uci commit` and the end of verify: the result is "Applied, not verified: <reason>", never done; the audit has every command sent (Task 5 test `test_apply_interrupted_after_commit_is_not_verified`).
3. A Wi-Fi key with `'`, `$`, a backtick, spaces or a non-ASCII character: the exact key lands in uci, and it is `<hidden>` in the preview, the audit log and the app log (Task 1 test `test_key_with_shell_metacharacters_is_quoted`; Task 5 test `test_key_never_reaches_preview_or_audit`).
4. Bench Guard goes live while a writable LuCI page is open, or the page sits idle: within one guard check the session is replaced by a read-only one (the page reloads read-only), and after 5 min idle the bridge closes and the rpcd session is destroyed (Task 13 tests `test_guard_live_downgrades_open_bridge`, `test_idle_bridge_is_closed_and_session_destroyed`).
5. A station leaves between samples, has no host hint, or the router stops answering mid-stream: RF live keeps sampling, marks the station "left", shows "—" for unknown values, sends `rf-idle` with the reason, and the CSV keeps the same columns (Task 11 tests `test_station_leaving_is_marked_left`, `test_csv_columns_stable_when_station_leaves`, `test_router_unreachable_sends_idle_and_keeps_running`).
